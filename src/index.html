Settings

Engine

Larger = longer chats but more VRAM/RAM. Changing engine settings restarts the model.
Measured on this PC (Gemma 4 26B, GPU): copy-ahead made "fix this config and return it" about 6x faster (64 → 396 tokens/s) with identical answers, and did not slow normal chat. 8-bit memory saved little at 8K context with this model but was 5–25% faster, with identical answers and 12/12 on the starter tests. Copy-ahead copies likely next words from the prompt and the model checks them, so the answer does not change, only the speed.

Assistant

Files & tools

Read-only, so it can answer "is the Print Spooler running?" itself. It can't change anything or see other computers, and every lookup is in the activity log. Like any tool, it turns off the "unsure value" underlines (the engine can't do both).
Read-only: the assistant can list, read and search text files inside these folders, nothing else. No writing, no commands, no network. Every access is recorded in the activity log.
Search index
Lets the assistant search by meaning across all files in the approved folders (code, configs, notes, Word, PDF). Runs on the CPU and only re-reads files that changed. Re-run after files change.

Screen memory (home only, experimental)

Reads only the window that is in front, as text, about every 30 seconds while it changes. No pictures are saved. Passwords, keys, tokens, card numbers and one-time codes are removed before anything is stored. Windows on the list below are never read. Nothing is captured while you are idle, locked, or paused. Everything stays on this computer (data\chats.db), so keep the drive encrypted. It only runs while OpenPort is open, and a red dot shows in the tray and the sidebar whenever it is recording. Hotkeys: Ctrl+Alt+P pause or resume, Ctrl+Alt+M remember the window in front.
Password managers, private-browsing windows, sign-in pages, banking and similar are listed by default. Removing a word means windows containing it WILL be read.

Answer checks

After each answer, every PowerShell command and parameter in it is looked up in this computer's own PowerShell. Made-up commands and wrong parameters get a red wavy underline, with a button to ask the model to fix them. Only the names are looked up: nothing from the answer is ever run. It does not check what a command does, the values, or whether it is safe.
Claim checks only read: service status, the installed-updates list, whether a local path exists, and the text of files in this conversation. Results are shown to you, not sent to the model. They describe THIS computer: if the answer is about another machine, they don't apply.

Smart context (experimental)

Both use the embedding model (CPU, low priority) to choose what goes into the model's limited window. Off by default. The first re-inserts old messages from the same chat when they look relevant; the second makes file tools return the matching parts of a large file instead of its first pages. You'll see a ↩ or a 🔧 line whenever they act.

Screen timeline

Search the text of windows you had in front of you. This is text read from the screen by OCR, so characters can be misread (0 and O, 1 and l, 5 and S): check exact values. Leave the box empty to see the most recent.

Memory

What OpenPort can bring back into a new chat. When you ask something, the closest few notes (by meaning, with a small preference for recent ones) are shown to the model. Words like "yesterday" or "last week" limit recall to that time. Notes marked outdated are kept here but never recalled. Everything stays in data\chats.db on this computer.

Save key facts from this chat

The model suggests short facts from the open chat (decisions, values, names). Edit or delete lines before saving. A saved fact that says nearly the same thing as an older one marks the older one outdated. Deleting the chat deletes its facts.

Mistake log: verified PowerShell facts

When the command checker catches the model using a command or parameter that doesn't exist on this PC, the true facts are saved here and given to the model next time a related question comes up. Only what this PC proved is saved (what doesn't exist, and what does), never a guess about the right fix. Each fact is re-checked before use and removed if it stops being true.

Everything remembered

Cartridges

A cartridge is a document the model has already read, saved to disk. Starting a chat from one skips re-reading it, which is much faster on a slow CPU. It only works with the model and context size it was made with.

Model tests

Your own questions with answers that can be checked automatically. Run them on any installed model to see how it really does on your work before you switch. Results never leave this computer.

Run

Testing a model that isn't loaded unloads the current one, runs the tests, then loads the previous one back. Close other apps first.
